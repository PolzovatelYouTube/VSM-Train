# Авторитетный пересчёт попытки

`POST /api/attempts` принимает только идентификатор игрока, режим, идентификатор
сценария и упорядоченный журнал действий:

```json
{
  "playerName": "Ирина Петрова",
  "scenarioId": 12,
  "mode": "check",
  "actions": [
    { "type": "choice", "nodeId": "medical-start", "choiceId": "call-medic", "timestampMs": 45120 }
  ]
}
```

Клиент не отправляет `score`, `loyalty`, `safety`, компетенции, XP или итоговый
журнал. Сервер загружает сохранённый сценарий, прогоняет `actions` через тот же
чистый `shared/engine.ts` и только затем сохраняет рассчитанные шкалы, результат
и журнал в SQLite.

Replay отклоняет действия вне длительности сценария, действия не по порядку,
ответ вне активного узла и вариант, скрытый условием сценария. Ручной запуск
разрешён только для событий с триггером `manual`. Если в режиме `check` ответ
не поступает до дедлайна, таймаут применяет сам сервер.

`timestampMs` — виртуальное время симуляции от начала рейса. Для production
версии следующим шагом следует создать серверную сессию рейса и подписывать
действия её идентификатором: это позволит измерять реальное wall-clock время
реакции без доверия к часам браузера.
