# Потребности доступности и ресурсы состава

Сценарий хранит наблюдаемые потребности отдельно от роли персонажа. `Actor.accessibilityNeeds` допускает `hearing`, `vision`, `wheelchair` и `mobility`. Например, медицинский инцидент в `onboard.ts` больше не маркирует пассажирку как `elderly`: возраст не определяет алгоритм помощи.

Вагон содержит факультативные `availableSeats` и `capabilities`: доступный санузел, место для коляски, письменный канал, визуальная информация, тихая зона и пространство для ухода. `ScenarioData.serviceEntitlements` описывает сервисы, доступные именно в учебном рейсе. Это операционные возможности сценария, а не заявление о юридических правах или обязательствах перевозчика.

Условия сценария поддерживают декларативные проверки ресурсов:

```ts
{ resource: { type: "availableSeats", carId, range: { gte: 1 } } }
{ resource: { type: "carType", carId, eq: "business" } }
{ resource: { type: "capability", carId, capability: "quietArea" } }
{ resource: { type: "serviceEntitlement", entitlement: "writtenCommunication" } }
```

Они проверяются движком из `SimState.resources`, созданного из `ScenarioData`; клиент не вычисляет доступность самостоятельно. Старые сценарии без этих полей получают пустые ресурсы и остаются совместимыми.

`accessibility.ts` включает отдельные ветки для нарушения слуха и зрения. В первой после уточнения доступен письменный/визуальный канал, если состав им оснащён. Во второй используются словесные ориентиры и предложение сопровождения. Это показывает разные способы помощи, а не единый ответ для любой потребности.

Добавлены три встроенных сценария: «Посадка под давлением», «Сервис по классу и оснащению» и «Доступная коммуникация». В них решение зависит соответственно от документов и свободного места, класса/оснащения вагона и согласованного канала общения.
